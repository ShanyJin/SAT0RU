## 2026-11-26 · 虚式「茈」投射模式（顶部按钮）

- 按参考视频做「茈」：食指+中指并拢、拇指外张的枪形蓄势；手心前上方出现紫色小球，发射后射向屏幕正中心。
- **按钮是模式开关，不是施法按钮**（主人纠正）：顶部正中「茈」点击后，枪形/捏合改为构筑茈；
  苍/赫全部暂停，避免三个术式抢同一手势。再点关闭恢复苍/赫。
- 发射两种：持续前推（复用苍的 `CHARGE` 连续增长链），或「食指+中指并拢、拇指在下，向外弹」；
  拇指外张的枪形弹指不会误触。松手/姿势丢失 280ms 取消蓄势，不进入冷却。
- 小球 700 点（紫罗兰核/环/雾），蓄势 700ms 展开 + 呼吸；飞行 380ms 加速到 `(0,0,0)`，命中点爆。
  爆炸源位置写 `0.0001` 防止目标形状回退；尘埃层同步炸开。
- **冷却统一 2 秒**：`TECH_COOLDOWN_MS 8000→2000`，苍的触发锁 `BLUE_SEQ.cooldownMs 2500→2000`；
  紫爆 `1600ms + postExplosionNeutralMs 400ms = 2s`；按钮外圈 conic-gradient 显示剩余冷却。
- 回归扩到 **39 项**（按钮开关、枪形/捏合蓄势、枪形不触发赫、松手取消、前推发射、命中、2s 冷却拦截/恢复、
  拇指在下弹指发射）；新增 `&end=purplecharge|purpleburst` 视觉演示。
- 顺手修指南里过期的「8 秒冷却」，并把茈的用法加到指南顶部。

## 2026-11-26 · 苍构筑锁定加固：只有持续前推才释放

- 主人实测：构筑后移动手、动手指或轻微动作就会释放；要求慢移时球跟手，只有大幅前甩（加速度过阈值）
  才释放。旧行为确实不对。
- **根因**（临时探针逐帧记录）：释放是「手速 / 掌尺寸增速 / 丢追踪」多通道 OR，且 120ms 窗口均值会把一次
  关键点跳变连续算作多帧 fast，`fastFrames 2` 根本滤不掉。实测 +22% 尺寸跳变第 2 帧释放、
  ~1.8/s 横向快挥第 4 帧释放、快速移动后丢追踪 260ms 也释放。
- **改法**：删掉手速与 `lostFastMs` 通道，只认持续前推——掌尺寸连续增长 ≥3 个采样、持续 ≥110ms、
  累计 ≥24%、平均增速 ≥1.7/s；任一采样不涨即断链。横向快挥/慢拖/转腕/指赫都只跟手。
  丢追踪宽限 700→1000ms，安全阀 15→30s。
- 回归 25/25 PASS：新增「手指/尺寸抖动不释放」「快速横向挥手不释放」，改写「持续前推释放」；
  `&end=blue` 视觉演示也改成前推触发。

## 决策备忘（不复盘会忘的）

1. **为什么单文件**：上游就是单文件，所有 PR 冲突的教训是「拆不动」。迁移到 Tasks API 时再考虑模块化。
2. **为什么识别要分数+EMA**：单帧硬判断猜错一次特效跳一次；EMA 让过渡平滑，代价是 ~150ms 延迟。
3. **为什么爆炸在屏幕中央**：主人明确指定；「跟随光球」版本已撤。
4. **为什么 8 秒冷却**：赫前甩后手回收会摆出苍的时序，实测必误触；冷却比「更聪明的判定」可靠。
5. **为什么待机粒子用独立尘埃层**：20k 主场待机全隐藏是性能闸门，不能为了待机氛围把它请回来；
   1200 颗独立点足够氛围、几乎不花帧。
6. **为什么技法用日文原版名**：主人点名不要「蓝无限」这类自造名。
7. **赫的两种手势为什么能共存**：同一技法两种入场券，切换/短暂丢手用 350ms 桥接，冷却只认「技法」不认「手势」。
