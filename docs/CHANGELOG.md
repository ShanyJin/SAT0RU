  进场 320 ms 淡入并上抬。無量空処额外要求「进黑幕前收」：`maybeTriggerVoidCinematic` 提前算好触发时刻，

  赫场闪断。现在赫在场时保持「两指朝上的姿势家族」并给拇指加迟滞（明确内扣到 0.58 以下才让出），

  另外粒子呼吸改成整体同相位、幅度 0.08 → 0.035、自转 1.15 → 0.55，跟手抽出纯函数
  `redFollowStep()`（200 ms 阻尼 + 0.8 死区 + 2.4 软过渡）。Xvfb 连续抽帧实测球心漂移

## 2026-11-27 · 赫的进入/退出拆成两套动画：激发 = 向前射出，退场 = 原地燃尽

- **症状**：赫进入与退出共用「目标形状 lerp 0.1/帧」——进入是慢慢浮出、退出是红场缓回中央淡出，
  两者看起来像同一段淡入淡出，主人反馈「总有一种激发失效的感觉」。
- **激发（进入）改成真正的射出**：`startRedCast` 在进入赫的那一帧记录指尖锚点与
  **手腕→指尖方向**（`redAnchor.aimX/aimY`；手几乎直指镜头时向量缩成噪声，保留上次稳定 aim，不侧射）。
  之后 420ms 内沿该方向**单向**打出 700 点红色枪矛（前 20% 点聚成高亮弹头，`lanceSpeed=170` 世界单位/秒，冲出红场），
  指尖同时 210ms 枪口闪光（520 点，bloom 临时 +1.5）、380ms 前向冲击锥（380 点，锥长 18≫半宽 4.2）；
  红场在这一刻压到 0.6 倍再弹过 1（阻尼弹簧），并沿 aim 反方向后退 3.4 作为后坐。
  所有特效严格限制在 aim 前方——**是向前打出去，不是径向炸开**。
- **退场（退出到中性）改成原地熄灭**：`startRedBurn` 把红场钉在离开时的位置，260 颗余烬以 24 单位/s²
  下落、620ms 淡出；切到别的技法不播燃尽，直接交给新目标形状。
- **实现**：`RED_CAST` 参数表 + `redCastLayout` / `redBurnLayout` 两个只依赖 age 的纯函数
  （回归可断言几何）；四组特效各自一个复用的 `THREE.Points`（`redLance/redFlash/redCone/redEmber`，
  共 1860 点，平时隐藏），逐帧填充只在 ≤0.62s 的演出窗口内发生，帧率优先。
- **回归 220→231 项**：新增「赫激发就以红场为起点 / 沿竖起的手指瞄准 / 从枪口闪光开始 / 随 age 前进 /
  保持细窄不是爆炸 / 按时收尾 / 红场回弹后坐 / 枪矛几何只向前」与「退出开始燃尽 / 燃尽是下落而非射出 /
  按时结束」；新增演示态 `&end=redcast&age=<ms>` 与 `&end=redburn&age=<ms>`（相位每帧重钉，
  软件渲染 1–3fps 也能截到同一时刻）。`LOGICTEST PASS · 231 assertions`。

## 决策备忘（不复盘会忘的）

1. **为什么单文件**：上游就是单文件，所有 PR 冲突的教训是「拆不动」。迁移到 Tasks API 时再考虑模块化。
2. **为什么识别要分数+EMA**：单帧硬判断猜错一次特效跳一次；EMA 让过渡平滑，代价是 ~150ms 延迟。
3. **为什么爆炸在屏幕中央**：主人明确指定；「跟随光球」版本已撤。
4. **为什么有全局冷却（现在 2 秒）**：赫前甩后手回收会摆出苍的时序，实测必误触；冷却比「更聪明的判定」可靠。最初取 8 秒，后按主人要求统一为 2 秒。
5. **为什么待机粒子用独立尘埃层**：20k 主场待机全隐藏是性能闸门，不能为了待机氛围把它请回来；
   1200 颗独立点足够氛围、几乎不花帧。
6. **为什么技法用日文原版名**：主人点名不要「蓝无限」这类自造名。
7. **赫的两种手势为什么能共存**：同一技法两种入场券，切换/短暂丢手用 350ms 桥接，冷却只认「技法」不认「手势」。
